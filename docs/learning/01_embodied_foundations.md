# 具身智能基础：把所有模块放进一个闭环

## 1. 什么叫“具身”

普通图像分类是一次性映射：

```text
image -> class
```

具身智能是循环：

```text
world -> sensor -> policy -> action -> controller -> world
  ^                                                   |
  +---------------------------------------------------+
```

动作会改变下一帧观测，所以模型不仅要“看懂”，还要预测自己的动作会造成什么后果。
这带来三个核心难点：

- **部分可观测**：一张 RGB 图看不到速度、遮挡物和接触力。
- **误差会累积**：一次小偏差会把机器人带到训练数据没覆盖的位置。
- **物理约束**：动作必须满足关节范围、碰撞、摩擦、控制频率和延迟。

本项目把整个闭环保留下来。语言指定任务，RGB 提供外观，proprioception 提供机器人自身
状态，策略输出连续动作，DLS-IK 把笛卡尔动作转换为关节目标，MuJoCo 再计算接触动力学。

## 2. State、observation 和 proprioception

### State

理论上的完整环境状态记作 \(s_t\)。在本项目中，privileged state 包含关节状态、末端位姿、
各物体位姿、目标位置和任务 one-hot。它适合：

- 调试仿真；
- 训练容易验证的 RL baseline；
- 计算奖励；
- 作为 teacher 或 oracle 上限。

它不适合直接冒充真实机器人输入，因为现实中无法无误差地读取所有物体世界坐标。

### Observation

策略实际看到的是 \(o_t\)。Tiny-VLA 使用：

- `rgb`: `3 x 64 x 64`
- `proprio`: 12 维
- `language`: 固定最大长度的 token id
- `language_mask`: 哪些 token 有效

观测由隐藏状态经过传感器模型产生：

\[
o_t \sim O(o_t \mid s_t)
\]

当一帧观测不足以恢复状态时，问题是 POMDP，而不是完全可观测 MDP。

### Proprioception

proprioception 是机器人的“本体感觉”，本项目包含关节位置和关节速度。真实系统还常包含：

- 电机电流或估计力矩；
- 夹爪开合；
- IMU；
- 末端力/力矩传感器；
- 控制器上一时刻命令。

它与 RGB 互补。RGB 擅长回答“物体在哪里、是什么”，proprioception 擅长回答“我自己在哪里、
正在怎么动”。

## 3. MDP 与 POMDP

MDP 可写为五元组：

\[
(\mathcal{S}, \mathcal{A}, P, R, \gamma)
\]

- \(\mathcal{S}\)：状态空间
- \(\mathcal{A}\)：动作空间
- \(P(s_{t+1}\mid s_t,a_t)\)：动力学
- \(R(s_t,a_t,s_{t+1})\)：奖励
- \(\gamma\)：折扣因子

目标是最大化期望折扣回报：

\[
J(\pi)=\mathbb{E}_{\pi}\left[\sum_{t=0}^{T-1}\gamma^t r_t\right]
\]

RGB 任务更准确地说是 POMDP，还需要 observation model。策略可以用历史近似 belief：

\[
\pi(a_t\mid o_{\le t},a_{<t},l)
\]

这里 \(l\) 是语言指令。当前 Tiny-VLA 使用单帧，所以无法显式估计速度和被遮挡物体。这是清晰的
模型边界，也是后续加入帧历史的理由。

## 4. 动作不是电机力矩

本项目的 5 维归一化动作：

```text
[delta_x, delta_y, delta_z, delta_wrist, jaw]
```

前三维是末端笛卡尔位移方向，第四维控制腕部，第五维控制夹爪。每维在 `[-1, 1]`，
环境再乘物理尺度。

这是一种中层 action space。常见层级还有：

| 动作空间 | 优点 | 缺点 |
| --- | --- | --- |
| 电机力矩 | 最接近动力学，可做精细控制 | 难学、频率高、sim-to-real 敏感 |
| 关节位置/速度 | 稳定，工业控制常用 | 任务几何不直观 |
| 末端位姿增量 | 易表达抓取和移动 | 需要 IK，受奇异位形限制 |
| 技能/选项 | 时域长、规划容易 | 依赖预定义技能 |

面试时必须说清：VLA 输出的不是“直接物理力矩”，而是被低层控制器执行的笛卡尔增量和夹爪命令。

## 5. 奖励、终止与成功

奖励是训练信号，不等于任务定义。一个合理的 pick-place 奖励可能包含：

- 末端靠近目标的势函数差；
- 抓住后的抬升奖励；
- 物体靠近目标区的势函数差；
- 成功稀疏奖励；
- 动作幅值或碰撞惩罚。

但成功条件必须单独定义。本项目要求物体先被抬起，再进入目标区，避免“初始化就在目标区”
产生假成功。

Gymnasium 区分：

- `terminated=True`：任务自然终止，例如成功或失败状态；
- `truncated=True`：外部时间上限截断。

这个区别会影响 value bootstrap。把 timeout 当 terminal 会错误地把未完成状态价值设为零。

## 6. 数据分布和闭环误差

行为克隆学习专家分布上的监督目标：

\[
\min_\theta\ \mathbb{E}_{(o,a)\sim D_{\text{expert}}}
[\ell(\pi_\theta(o),a)]
\]

训练时输入来自专家轨迹，部署时输入来自模型自己造成的轨迹。只要前面一个动作略偏，
后面就可能进入数据集未见状态，这叫 covariate shift。

所以：

- 离线 action MAE 只能检查拟合；
- 真正任务能力要用 closed-loop success；
- 失败轨迹比单个平均数更有价值；
- DAgger、数据增强、恢复示范和 RL fine-tuning 都是在改善这个问题。

## 7. 任务语言究竟做了什么

本项目一张场景里有红、绿、蓝三个方块和左右两个目标区。语言决定：

```text
pick the green cube and place it on the left target
```

相同 RGB 和 proprioception 配上不同指令，正确动作应改变。这个反事实测试比“换一句同义词”
更能证明模型是否使用了语言。

如果训练集中只有一种颜色和一个目标，模型即使完全忽略语言也能成功。那不是有说服力的 VLA。

## 8. 评测的四层证据

1. **单元级**：张量形状、动作范围、确定性、终止逻辑。
2. **离线级**：episode-disjoint validation MAE、phase accuracy、grounding error。
3. **闭环级**：未见随机种子的成功率、耗时、失败类型。
4. **系统级**：ROS topic、TF、地图、延迟、资源占用和可复现命令。

任何简历数字都应该能回到一份机器生成的 JSON，而不是手工写在 README 里。

## 9. Sim-to-real 边界

仿真成功不自动等于真机成功。主要 gap 包括：

- 几何和标定误差；
- 摩擦、质量和电机响应误差；
- 相机曝光、纹理和背景变化；
- 控制延迟、丢帧和网络抖动；
- 夹爪形变和接触模型差异；
- 真机安全约束。

本项目用 domain randomization、归一化、稳定中层动作接口和 ROS 边界为迁移做准备，但没有真机
实验时，简历必须写“MuJoCo 仿真验证”，不能写“部署到 SO101 真机”。

## 10. 一句话串起整个项目

> 这是一个语言条件的部分可观测控制问题：策略从 RGB、本体状态和指令估计当前任务相关状态，
> 预测一段连续末端动作，由 IK 与关节控制器执行，并在 MuJoCo 接触动力学中用闭环成功率验证；
> PPO 提供在线强化学习基线，ROS2 和 SLAM 则验证系统通信与移动感知能力。
